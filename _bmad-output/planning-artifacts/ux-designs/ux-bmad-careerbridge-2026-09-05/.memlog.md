- (event) Fast path, Create intent. Sources: PRD prd.md + addendum.md (screen inventory, seed cast), ARCHITECTURE-SPINE.md (ARCH-06/07/09/11, S1, S6, S9, S10), brief + addendum (demo script). No web research, no creative tools, no external handoffs, no reviewer gate; Oleg reviews, Josh (Design Engineer) owns UX and reacts.
- (decision) Component library: MUI 7 (ARCH-07 default kept). Reasons: accessible labelled form controls and keyboard support out of the box (NFR-9), responsive Grid/Drawer at 375 px (NFR-8), Table/Tabs/Badge/Stepper/Chip/Dialog cover every screen, five developers with mixed React experience need one documented vocabulary. Rejected: Tailwind + shadcn (copy-paste ownership plus a11y work lands on the team), hand-rolled CSS (fails ARCH-07).
- (decision) Form factor: responsive single-origin web. Public and Applicant surfaces mobile-first from 375 px; Recruiter and Admin surfaces desktop-first (tables) but operable at 375 px via stacked cards. No native apps (A-28).
- (decision) Navigation: one MUI AppBar for all roles; links per role; bell with Badge = unread count (FR-A5-1) polled by TanStack Query; avatar menu with Log out. Under 900 px links collapse into a Drawer. Routes mirror S10 scopes: /, /jobs/:id, /login, /register, /recruiters/request (public); /me/* (applicant); /org/* (recruiter); /admin/* (administrator); /notifications shared.
- (decision) Stage display keyed to stored enum (S1), label from stage_labels (FR-M4-3): every Stage is a Chip with label + icon (never colour alone, NFR-9); Application detail shows a 5-step Stepper Applied>Screening>Interview>Offer>Hired plus a terminal Chip for rejected/withdrawn/declined; history list from audit (S5) with rejection reason verbatim in an Alert; interview card when recorded (A-7).
- (decision) Refusals: one <ErrorAlert> maps S9 codes to treatment. validation_failed -> inline helper text; application_cap_reached -> Alert on Job Detail with count and cap (FR-A3-4), Apply stays enabled so the server refuses; profile_incomplete -> Alert linking /me/profile (FR-A3-2); duplicate_application -> Apply replaced by 'You applied' link; forbidden -> full-page 'You do not have access', no record data (FR-R3-3); not_found -> 'This posting is not available'; invalid_transition / concurrent_change -> Alert on detail with server message verbatim, then refetch (NFR-4). Client hides actions invalid for the current Stage; server is the authority (NFR-1).
- (assumption) A-UX-1 unread poll 30 s. A-UX-2 confirmation Dialog for every terminal or notified action (reject, offer, accept, decline, withdraw, close, suspend); approvals are one click plus snackbar. A-UX-3 Job Detail shows 'N of CAP active applications' hint when logged in. A-UX-4 Admin queues are two routes sharing one Tabs layout. A-UX-5 Brand: navy primary, amber reserved for Offer; Roboto (MUI default). A-UX-6 Landing after login: applicant /me/applications, recruiter /org/postings, admin /admin/requests.
- (assumption) A-UX-7 Recruiter queue offers inline row actions (advance, reject, record interview, extend offer) as well as the same actions on the detail page.
